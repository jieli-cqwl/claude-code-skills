# UNIT 文件规格

> /prd 生成的语义拆解单元格式定义。

---

## UNIT 文件结构

每个 UNIT 文件是一个独立的语义闭环单元，包含完整的需求定义、验收标准和边界条件。

```markdown
# UNIT-NNN: [需求标题]

## 背景
[需求存在的业务背景和动机]

## 需求描述
[做什么、为什么]

## 验收标准

### 正常场景
- [输入/操作] → [期望输出]
- [输入/操作] → [期望输出]

### 异常场景
- [输入/操作] → [期望错误/拒绝]
- [输入/操作] → [期望错误/拒绝]

### 边界条件
- [边界条件] → [期望行为]
- [边界条件] → [期望行为]

## 业务规则（如有）
- [适用的业务约束]

## 依赖
- 依赖 UNIT: [UNIT-NNN 列表，无则标"无"]
- 依赖数据: [数据实体或状态，无则标"无"]

## 排除项
- [本需求明确不处理的场景]
```

---

## 命名规范

| 字段 | 格式 | 示例 |
|------|------|------|
| 文件名 | `UNIT-NNN_简短标题.md` | `UNIT-001_用户名校验.md` |
| UNIT ID | `UNIT-NNN`（3 位零填充） | `UNIT-001` |
| 验收标准 | `[输入/操作] → [期望输出]` | `"alice" → 201 Created` |

---

## 质量标准

| 检查项 | 要求 |
|--------|------|
| 背景 | 说明需求的业务动机（不是技术动机） |
| 需求描述 | 做什么、为什么——精确、无歧义 |
| 正常场景 | ≥ 1 个，包含输入和期望输出 |
| 异常场景 | ≥ 1 个，包含输入和期望错误 |
| 边界条件 | ≥ 1 个，覆盖最小值/最大值/空值/特殊字符 |
| 业务规则 | 如有适用的业务约束，显式列出 |
| 依赖 | 明确列出与其他 UNIT 的关系 |
| 排除项 | 明确本需求不负责的场景 |
