# 输出模板

## 精简版模板

适用条件：<=2 模块且接口 <=3 个（DDS 内联）

```markdown
# handoff_design.md

## Goals / Non-Goals
### Goals
- [G1: ...]
### Non-Goals
- [NG1: 本可以成为目标但被排除的事项...]

## 输入分析
[扫描现有代码的发现 + 需求规则逐条理解 + 适用规范识别]

## 架构视图（可选）
> 涉及多模块交互时建议绘制，单模块内部改动可省略

## 技术选型（含决策记录）
### 决策点：{name}
| 维度 | 方案 A | 方案 B |
|------|--------|--------|
| 与现有代码一致性 | ... | ... |
| 实现复杂度 | ... | ... |
| 可维护性 | ... | ... |
- 决策：...
- 理由：...
- decision_status: USER_CONFIRMED | AUTO_DECISION

## 产出
### 模块索引
### 接口清单

> 精简版接口（≤3 接口且非全栈）使用简化表格：

| 接口 | 入参 | 出参 | 关键错误码 |
|------|------|------|-----------|
| {METHOD} {PATH} | {字段: 类型, ...} | {STATUS_CODE} {响应结构} | {STATUS_CODE} {ERROR_CODE} |

### 数据模型（如有）
### 实施约束（可翻译为 assert）

## Open Questions
[待确认假设，无则标"无待确认项"]

## 覆盖表
[需求规则 -> 设计产出 -> 覆盖状态]

## 交接项
```

## 完整版模板

适用条件：>2 模块或接口 >3 个（输出 MOD 文件）

```markdown
# handoff_design.md

## Goals / Non-Goals
### Goals
- [G1: ...]
### Non-Goals
- [NG1: 本可以成为目标但被排除的事项...]

## 输入分析
[扫描现有代码的发现 + 需求规则逐条理解 + 适用规范识别]

## 架构视图
[Mermaid C4 System Context 图 + Container 图，强制要求]

## 技术选型（含决策记录）
### 决策点：{name}
| 维度 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 与现有代码一致性 | ... | ... | ... |
| 实现复杂度 | ... | ... | ... |
| 可维护性 | ... | ... | ... |
- 决策：...
- 理由：...
- decision_status: USER_CONFIRMED | AUTO_DECISION

## 产出
### 模块索引（指向 design/MOD-*.md）
### 接口清单（或"接口规格"专节）

> 标准版接口（4-10 接口）使用结构化模板，每个接口包含：
> 入参表格 + 出参 JSON 示例 + 错误码表 + 边界行为表。
> 模板详见 SKILL.md §6.4 "结构化接口模板"。
>
> 增强版接口（>10 或对外 API）输出独立的 `design/API-SPEC.md`，此处仅放索引。

### 数据模型（如有）

## 横切关注点
[安全、隐私、可观测性、错误监控]

## Open Questions
[待确认假设]

## 成功指标
[可量化的验收标准]

## 覆盖表
[需求规则 -> 设计产出 -> 覆盖状态]

## 交接项
```

```markdown
# MOD-001: {模块名}

## 模块职责
- 负责：...
- 不负责：...

## 现有代码集成点
- 复用：...
- 新建：...

## 适用规范
| 规范 | 关键约束 |
|------|---------|
| ... | ... |

## 接口设计

> 使用结构化模板定义每个接口（模板详见 SKILL.md §6.4）：

### {METHOD} {PATH}

**描述**: {一句话说明}

**入参**:

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|---------|------|
| ... | ... | ... | ... | ... |

**出参（成功 {STATUS_CODE}）**:
```json
{ "结构化示例" }
```

**错误码**:

| HTTP 状态码 | error_code | 触发条件 | 用户消息 key |
|------------|------------|---------|-------------|
| ... | ... | ... | ... |

**边界行为**:

| 场景 | 预期行为 |
|------|---------|
| ... | ... |

## 数据模型（如有）
- 字段/索引/关系

## 运行时视图
- 主流程
- 异常分支

## 实施约束
1. ...

## 模块依赖
- 依赖：...
- 被依赖：...
```
