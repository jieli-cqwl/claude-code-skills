# UNIT 文件规格

> /prd 生成的语义拆解单元格式定义。

---

## UNIT 文件结构

每个 UNIT 文件是一个独立的语义闭环单元，包含完整的规则定义、示例和边界条件。

```markdown
# UNIT-NNN: [规则标题]

## 背景
[规则存在的业务背景和动机]

## 规则描述
[精确的规则定义]

## 验收标准

### 正例
- [输入] → [期望输出]
- [输入] → [期望输出]

### 反例
- [输入] → [期望错误/拒绝]
- [输入] → [期望错误/拒绝]

### 边界
- [边界条件] → [期望行为]
- [边界条件] → [期望行为]

## 依赖
- 依赖 UNIT: [UNIT-NNN 列表，无则标"无"]
- 依赖数据: [数据实体或状态，无则标"无"]

## 排除项
- [本规则明确不处理的场景]
```

---

## 命名规范

| 字段 | 格式 | 示例 |
|------|------|------|
| 文件名 | `UNIT-NNN_简短标题.md` | `UNIT-001_用户名校验.md` |
| UNIT ID | `UNIT-NNN`（3 位零填充） | `UNIT-001` |
| 正例/反例 | `[输入] → [期望输出]` | `"alice" → 201 Created` |

---

## 质量标准

| 检查项 | 要求 |
|--------|------|
| 背景 | 说明规则的业务动机（不是技术动机） |
| 规则描述 | 精确、无歧义、可翻译为代码逻辑 |
| 正例 | ≥ 1 个，包含输入和期望输出 |
| 反例 | ≥ 1 个，包含输入和期望错误 |
| 边界 | ≥ 1 个，覆盖最小值/最大值/空值/特殊字符 |
| 依赖 | 明确列出与其他 UNIT 的关系 |
| 排除项 | 明确本规则不负责的场景 |
