# 简单模式输出规范

> 规则 ≤ 3 条且单模块时使用。输出单个 master.md，规则直接内联。

---

## master.md 模板

```markdown
# PRD: [功能标题]

**功能名**: {feature_name}
**产出时间**: YYYY-MM-DD
**模式**: 简单（规则内联）

---

## 业务背景
[为什么需要这个功能]

## 用户故事
作为 [角色]，我希望 [动作]，这样 [价值]。

## 功能规则

### 规则 1：[标题]
**描述**: [规则描述]
- 正例：[输入] → [期望输出]
- 反例：[输入] → [期望错误]
- 边界：[边界条件] → [期望行为]

### 规则 2：[标题]
...

## 排除项
- [明确不做的事情]

## 技术约束
- [来自项目规范的约束]

## 交接项
- 规则数量: X 条
- 正例总数: X 个
- 反例总数: X 个
- 边界总数: X 个
```

## 完整示例

需求：「给用户注册接口加上邮箱格式校验」

```markdown
# PRD: 用户注册邮箱校验

**功能名**: email-validation
**产出时间**: 2026-02-28
**模式**: 简单（规则内联）

---

## 业务背景
当前用户注册接口不校验邮箱格式，导致无效邮箱进入系统，影响后续通知功能。

## 用户故事
作为注册用户，我希望系统校验邮箱格式，这样我不会因输入错误的邮箱而收不到重要通知。

## 功能规则

### 规则 1：邮箱格式校验
**描述**: 注册时校验邮箱符合 RFC 5322 基本格式（local@domain）
- 正例：`user@example.com` → 注册成功（201）
- 正例：`user.name+tag@domain.co.uk` → 注册成功（201）
- 反例：`user@` → 返回 422，提示"邮箱格式无效"
- 反例：`@domain.com` → 返回 422，提示"邮箱格式无效"
- 反例：`plaintext` → 返回 422，提示"邮箱格式无效"
- 边界：空字符串 → 返回 422，提示"邮箱不能为空"

### 规则 2：邮箱唯一性
**描述**: 同一邮箱不允许重复注册
- 正例：`new@example.com`（未注册） → 注册成功（201）
- 反例：`existing@example.com`（已注册） → 返回 409，提示"邮箱已被注册"
- 边界：大小写不同 `User@Example.COM` vs `user@example.com` → 视为同一邮箱

## 排除项
- 不做邮箱可达性验证（发送验证邮件）
- 不做一次性邮箱检测

## 技术约束
- 校验在 API 层完成，不依赖前端校验
- 错误提示面向用户，不暴露技术细节

## 交接项
- 规则数量: 2 条
- 正例总数: 3 个
- 反例总数: 5 个
- 边界总数: 2 个
```
