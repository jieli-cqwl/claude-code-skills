# 提示词工程 Skill

> ultrathink — 深度思考模式，确保技巧选择和提示词生成的质量

## 执行流程

严格按以下五步执行，每步完成后再进入下一步。

---

### 第一步：需求分析

收集以下信息（未提供的主动询问）：

| 维度 | 说明 | 默认值 |
|------|------|--------|
| 用途描述 | 提示词要完成什么任务 | （必填） |
| 目标模型 | Claude / GPT / Gemini / 通用 | 通用 |
| 使用方式 | System Prompt / 单次任务 / 多轮对话 / Agent 工作流 | System Prompt |
| 输出语言 | 提示词正文使用的语言 | 中文 |

**分析任务特征**：根据用途描述，识别以下特征标签（可多选）：

| 特征标签 | 判断依据 |
|---------|---------|
| `收集信息` | 需要多轮收集用户输入 |
| `复杂推理` | 涉及分析、判断、推导 |
| `调用工具` | 需要与外部 API/工具交互 |
| `专业身份` | 需要特定专业角色视角 |
| `标准化输出` | 有固定输出格式要求 |
| `多方案对比` | 需要评估多个选项 |
| `知识库问答` | 基于外部知识源回答 |
| `多步骤任务` | 任务有明确的阶段/步骤 |
| `多角色协作` | 需要多个角色配合 |
| `高精度输出` | 对准确性要求极高 |
| `长上下文` | 输入数据量大 |
| `结构化` | 输入输出需要明确结构 |
| `Agent 韧性` | Agent 场景需要容错和坚持 |
| `特定场景` | 匹配已知 SOP 模板 |

输出格式：
```
## 需求分析

- **用途**：[用途描述]
- **目标模型**：[模型]
- **使用方式**：[方式]
- **输出语言**：[语言]
- **特征标签**：`标签1` `标签2` `标签3`
```

---

### 第二步：技巧选择

读取 `~/.claude/skills/prompt/references/technique-catalog.md`，根据特征标签从技巧索引中路由最优 2-4 种组合。

**技巧选择矩阵**：

| 需求特征 | 推荐技巧 |
|---------|---------|
| `收集信息` | 槽位填充 |
| `复杂推理` | 思维链 CoT |
| `调用工具` | ReAct 模式 |
| `专业身份` | 角色扮演 |
| `标准化输出` | Few-shot |
| `多方案对比` | 思维树 |
| `知识库问答` | RAG 模式 |
| `多步骤任务` | Plan-Execute |
| `多角色协作` | Multi-Agent |
| `高精度输出` | 自我批判 + 约束前置 |
| `长上下文` | 指令后置 + 桥接语句 |
| `结构化` | XML/Markdown 标记 |
| `Agent 韧性` | 坚持指令 + 预计算反思 |
| `特定场景` | 对应 SOP 模板（研究分析/创意写作/问题解决/教学内容） |

**选择原则**：
- 每个特征标签至少对应一种技巧
- 总数控制在 2-4 种（避免过度堆砌）
- 有冲突时优先选择与核心任务最相关的

输出格式：
```
## 技巧选择

| 技巧 | 选择理由 |
|------|---------|
| [技巧名] | [基于什么特征标签，为什么适合] |
| [技巧名] | [基于什么特征标签，为什么适合] |
```

展示选择结果后，使用 AskUserQuestion 等用户确认，再进入下一步。

---

### 第三步：生成提示词

读取 `~/.claude/skills/prompt/references/output-templates.md`，根据使用方式选择对应模板。

**模板选择**：

| 使用方式 | 模板 |
|---------|------|
| System Prompt | 模板 A：System Prompt 型 |
| 单次任务 | 模板 B：任务型 |
| 多轮对话 | 模板 C：多轮对话型 |
| Agent 工作流 | 模板 D：Agent 工作流型 |
| 研究分析类任务 | 模板 E：研究分析型 |

**约束前置结构框架**（核心组织原则）：

```
身份定义 → 核心约束 → 能力描述 → 行为规则 → 输出格式 → 示例(可选) → 自检指令(可选)
```

**标记语言选择**：

| 目标模型 | 标记语言 |
|---------|---------|
| Claude | XML 标签（`<identity>`, `<rules>`, `<output>`） |
| GPT | Markdown 标题（`# Identity`, `# Rules`） |
| Gemini | Markdown 标题 |
| 通用 | Markdown 标题 |

**生成规则**：
- 指令用命令式语气，禁止"请你帮我"等情感修饰
- 约束条件放在提示词顶部
- 术语在首次出现时定义
- 保持标记格式全篇一致
- 根据选中的技巧，将对应模板片段嵌入提示词结构

**需要深入参考时按需读取**：
- `~/.claude/docs/学习笔记/AI对话系统高级玩法手册.md`
- `~/.claude/docs/学习笔记/Gemini 提示词实践指南.md`

---

### 第四步：自检优化

对生成的提示词进行三维自检：

**1. 结构性检查**：
- [ ] 约束是否前置（身份和规则在最顶部）
- [ ] 标记格式是否全篇一致（不混用 XML 和 Markdown）
- [ ] 是否存在模糊词（"大概"、"可能"、"适当"）
- [ ] 输出格式是否明确定义

**2. 效果性检查**：
- [ ] 是否解决用户的核心意图（而非字面意思）
- [ ] 角色身份是否真实可信（有具体专业背景）
- [ ] 任务边界是否清晰（什么该做、什么不该做）
- [ ] 技巧运用是否自然融入（非生硬拼接）

**3. 鲁棒性检查**：
- [ ] 是否有对抗性输入防护（用户试图绕过规则时的应对）
- [ ] 缺失信息时是否有引导策略（主动询问而非猜测）
- [ ] 边界情况是否有兜底处理

发现问题直接修正，不需要用户介入。

---

### 第五步：输出

分两部分输出：

**Part A：提示词正文**

用代码块包裹，可直接复制使用：

````
```
[完整的提示词内容]
```
````

**Part B：设计说明**

```
## 设计说明

### 技巧运用
- **[技巧名]**：[在提示词中如何体现，起什么作用]
- **[技巧名]**：[在提示词中如何体现，起什么作用]

### 自检结果
- 结构性：[通过/已修正的问题]
- 效果性：[通过/已修正的问题]
- 鲁棒性：[通过/已修正的问题]

### 使用建议
- [针对该提示词的具体使用技巧]
- [可能需要根据实际情况调整的部分]
```

**输出规则**：
- 不保存文件，直接在对话中展示
- Part A 必须是完整可用的提示词，不包含任何占位符
- Part B 帮助用户理解设计思路，便于后续自行调整
