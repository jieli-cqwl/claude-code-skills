## 一、对话理解

### 1. 槽位填充 (Slot Filling)

**定义**：通过多轮对话收集完成任务所需的完整信息

**适用场景**：`收集信息` — 订票、表单、配置收集等需要逐步获取参数的场景

**效果**：确保必填信息完整，可选信息有默认值，减少一次性输入负担

**模板片段**：
```
你需要收集以下信息才能执行任务：
- [参数1]（必填）：[说明]
- [参数2]（必填）：[说明]
- [参数3]（可选，默认[值]）：[说明]

当用户提供需求时，提取已有信息。缺失必填项时主动询问，每次只问一个问题。
所有必填信息收集完成后，确认信息并执行任务。
```

### 2. 上下文管理 (Context Management)

**定义**：在长对话中维持信息连贯性，正确处理指代和省略

**适用场景**：`长上下文` — 长文档处理、多轮深入讨论、跨话题引用

**效果**：避免长对话中信息丢失和指代混乱

**模板片段**：
```
关键信息前置。对话中提到的重要决定和约束，在后续回复中主动引用确认。
当对话超过 [N] 轮时，在回答前简要总结当前状态和关键决定。
遇到指代不明时，明确确认而非猜测。
```

## 二、推理增强

### 3. 思维链 CoT (Chain of Thought)

**定义**：展示逐步推理过程，提高复杂问题准确率

**适用场景**：`复杂推理` — 数学计算、逻辑推导、代码分析、因果判断

**效果**：数学准确率+20-30%，逻辑推理+15-25%，代码调试效率+40%

**注意**：简单查询不要用（增加延迟），只在需要多步推导时启用

**模板片段**：
```
在给出结论前，按以下步骤展示推理过程：
1. 明确问题的核心是什么
2. 列出已知条件和约束
3. 逐步推导，每步说明依据
4. 得出结论并验证是否满足所有条件
```

### 4. 思维树 (Tree of Thoughts)

**定义**：探索多个解决方案分支，评估后选择最优路径

**适用场景**：`多方案对比` — 技术选型、架构设计、复杂问题诊断

**效果**：避免锚定在第一个想到的方案上，系统性地对比优劣

**模板片段**：
```
对于此问题，请：
1. 提出至少 3 种不同的解决方案
2. 对每种方案分析优缺点和适用条件
3. 评估实施成本和预期效果
4. 给出推荐方案及理由
```

## 三、行为增强

### 5. ReAct 模式 (Reasoning + Acting)

**定义**：思考-行动-观察的循环模式，边推理边执行

**适用场景**：`调用工具` — 需要调用外部 API、搜索、代码执行器的场景

**效果**：确保工具调用有明确目的，避免盲目调用

**模板片段**：
```
遵循"思考-行动-观察"循环：
- 思考：分析当前状态，决定下一步需要什么信息或操作
- 行动：调用合适的工具获取信息或执行操作
- 观察：分析工具返回结果，判断是否足够回答问题
重复循环直到获得足够信息给出完整回答。
```

### 6. 角色扮演 (Role Playing)

**定义**：设定具体身份和专业背景，激活领域知识

**适用场景**：`专业身份` — 代码审查、医疗咨询、法律分析等需要专业视角的场景

**效果**：输出更具专业深度，从"没发现问题"升级为"发现3个风险点+改进方案"

**模板片段**：
```
你是[具体身份]，拥有[N]年[领域]经验。
你擅长[核心技能列表]。
你的风格是[具体特点]。
在[工作场景]时，你会：
1. [具体行为1]
2. [具体行为2]
3. [具体行为3]
```

### 7. Few-shot (少样本学习)

**定义**：提供 3-5 个高质量示例，让模型学习输入输出模式

**适用场景**：`标准化输出` — 格式转换、数据提取、风格统一

**效果**：确保输出格式精确一致，减少格式偏差

**注意**：示例要有代表性且格式一致，3-5 个最佳

**模板片段**：
```
以下是几个示例，展示期望的输入输出格式：

示例 1：
输入：[例子1输入]
输出：[例子1输出]

示例 2：
输入：[例子2输入]
输出：[例子2输出]

示例 3：
输入：[例子3输入]
输出：[例子3输出]

现在请按照同样的格式处理：
输入：[实际输入]
```

## 四、工作流

### 8. Plan-Execute (计划-执行)

**定义**：先制定详细计划，再逐步执行并验证

**适用场景**：`多步骤任务` — 多阶段项目、复杂功能开发、系统性调研

**效果**：可追溯、可恢复、可评审，防止遗漏步骤

**模板片段**：
```
执行任务前先制定计划：
1. 将任务拆解为有序子任务
2. 标注每个子任务的依赖关系
3. 按依赖顺序逐步执行
4. 每步执行后验证结果，确认通过再进入下一步
5. 全部完成后回顾验收标准
```

### 9. Multi-Agent (多角色协作)

**定义**：多个角色各负其责，通过协作完成复杂任务

**适用场景**：`多角色协作` — 需要不同视角审视的任务（开发+审查+测试）

**效果**：多角度覆盖，减少单一视角的盲区

**模板片段**：
```
以下角色依次工作：
- **[角色A]**：负责[职责]，输出[产物]
- **[角色B]**：基于角色A的输出，负责[职责]，输出[产物]
- **[角色C]**：基于前两者的输出，负责[职责]，给出最终结果

每个角色独立完成自己的部分后，交给下一个角色。
```

### 10. RAG 模式 (检索增强生成)

**定义**：先从知识源检索相关信息，再基于检索结果生成回答

**适用场景**：`知识库问答` — 企业知识库、文档问答、带引用的研究报告

**效果**：回答有据可查，减少幻觉，支持溯源

**模板片段**：
```
回答问题时遵循以下流程：
1. 从提供的资料中检索与问题最相关的段落
2. 基于检索到的内容组织回答
3. 每个关键论点必须标注出处 [来源编号]
4. 如果资料中没有相关信息，明确说明"提供的资料中未涉及此内容"，不要编造
```

## 五、通用原则（源自 Gemini 实践指南）

### 11. 精准指令 (Precise Instructions)

**定义**：直接、清晰的命令式指令，拒绝废话和情感修饰

**适用场景**：所有场景 — 作为基础原则始终应用

**效果**：减少歧义，提高指令执行准确率

**要点**：
- 不用"请你帮我"、"这对我很重要"
- 命令式语气："分析..."、"列出..."、"输出..."
- 模棱两可的词汇在开头明确定义

### 12. 约束前置 (Constraints First)

**定义**：将所有行为约束和角色定义放在提示词最顶端，锚定推理起点

**适用场景**：`高精度输出` — 对输出有严格要求时

**效果**：防止模型在生成过程中跑偏，约束作为推理锚点始终生效

**要点**：
- 身份定义 → 核心约束 → 然后才是具体任务
- 绝对禁止的行为用"禁止"、"不得"明确标注
- 输出格式约束放在规则区而非末尾

### 13. 结构化提示 (Structured Prompting)

**定义**：使用标记语言界定提示词的不同区域

**适用场景**：`结构化` — 复杂提示词、含数据输入的场景

**效果**：帮助模型区分指令和数据，减少指令注入风险

**要点**：
- Claude → XML 标签：`<identity>`, `<rules>`, `<context>`
- GPT/Gemini/通用 → Markdown 标题：`# Identity`, `# Rules`
- 选定一种后全篇一致，不混用

### 14. 自我批判 (Self-Critique)

**定义**：要求模型在输出最终响应前进行自我校验

**适用场景**：`高精度输出` — 对准确性要求高的任务

**效果**：捕获幻觉和遗漏，提升输出可靠性

**模板片段**：
```
在给出最终回答前，执行自检：
1. 我是否回答了用户的真正意图（而非仅字面意思）？
2. 语气和风格是否符合设定的身份？
3. 如果因信息不足做了假设，是否已标注？
发现问题直接修正后再输出。
```

### 15. 自我更新任务清单 (Self-Updating TODO)

**定义**：在长任务中维护动态任务清单，跟踪进度

**适用场景**：`多步骤任务` — 长任务执行中保持状态

**效果**：防止长任务中遗漏步骤，保持执行状态可见

**模板片段**：
```
创建任务清单跟踪进度：
- [ ] 主要目标
- [ ] 任务 1
- [ ] 任务 2
- [ ] 最终审查
每完成一项，更新清单状态后再继续下一项。
```

### 16. 场景 SOP 模板

**定义**：针对特定场景的标准处理流程

**适用场景**：`特定场景` — 匹配以下四种场景之一

#### 研究分析 SOP
```
1. 将主题分解为关键研究问题
2. 针对每个问题独立检索/分析来源
3. 将发现综合为连贯报告
4. 引用规则：每个具体论断必须引用来源。无来源时注明"一般性估计"
```

#### 创意写作 SOP
```
1. 明确目标受众和写作目的（共情 vs 权威）
2. 如果任务要求亲切或随意风格，严格避免行业术语
3. 起草内容
4. 内部审读：这像人写的还是模板生成的？如果像模板，重写
```

#### 问题解决 SOP
```
1. 用自己的话重述问题
2. 找出"标准解决方案"
3. 找出"高级解决方案"（大多数人忽略的技巧或工具）
4. 优先呈现最有效的方法
5. 最终检查：这是否解决了根本问题？
```

#### 教学内容 SOP
```
1. 根据用户提问评估其当前知识水平
2. 在使用专业术语前先定义它
3. 用贴切的类比解释概念
4. 在结尾提供一个"理解检查"问题
```

## 长上下文处理技巧

**指令后置**：处理大量数据时，将任务指令放在数据末尾

**桥接语句**：在数据和指令之间插入过渡句："基于上述提供的所有信息，请执行以下任务..."

## Agent 韧性技巧

**坚持指令**：明确写入"必须持续工作直到问题被完全解决。工具调用失败时分析原因并尝试替代方案，不得直接放弃"

**预计算反思**：调用工具前强制三问："为什么调用？期望获取什么数据？这如何帮助解决用户的问题？"
