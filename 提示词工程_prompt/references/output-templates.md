# 提示词结构模板

> 五种场景的提示词骨架模板，生成时根据使用方式选择对应模板，填入技巧内容

---

## 模板 A：System Prompt 型

**适用**：长期运行的对话系统、助手角色定义

**标记语言**：根据目标模型选择 XML 或 Markdown

### XML 版（Claude）

```xml
<identity>
你是[身份]，拥有[背景]。
你擅长[核心技能]。
</identity>

<constraints>
- [绝对约束1：用"禁止"/"不得"标注]
- [绝对约束2]
- [输出格式约束]
</constraints>

<capabilities>
你能够：
1. [能力1]
2. [能力2]
3. [能力3]
</capabilities>

<rules>
在工作时遵循以下规则：
1. [行为规则1]
2. [行为规则2]
3. [行为规则3]
</rules>

<output_format>
[输出的结构定义，如 JSON schema、Markdown 模板等]
</output_format>

<examples>
[可选：2-3 个示例]
</examples>

<self_check>
[可选：自检指令]
</self_check>
```

### Markdown 版（GPT / Gemini / 通用）

```markdown
# Identity

你是[身份]，拥有[背景]。
你擅长[核心技能]。

# Constraints

- [绝对约束1：用"禁止"/"不得"标注]
- [绝对约束2]
- [输出格式约束]

# Capabilities

你能够：
1. [能力1]
2. [能力2]
3. [能力3]

# Rules

在工作时遵循以下规则：
1. [行为规则1]
2. [行为规则2]
3. [行为规则3]

# Output Format

[输出的结构定义]

# Examples

[可选：2-3 个示例]

# Self-Check

[可选：自检指令]
```

## 模板 B：任务型

**适用**：单次任务执行，如数据处理、内容生成、分析报告

```markdown
# Task

[一句话描述任务目标]

# Input

[输入数据或待处理内容的描述/占位]

# Steps

按以下步骤执行：
1. [步骤1]
2. [步骤2]
3. [步骤3]

# Constraints

- [约束1]
- [约束2]

# Examples

示例 1：
输入：[示例输入]
输出：[示例输出]

示例 2：
输入：[示例输入]
输出：[示例输出]

# Output Format

[明确的输出结构要求]
```

## 模板 C：多轮对话型

**适用**：需要多轮交互收集信息、逐步引导的场景

```markdown
# Identity

你是[身份]，负责通过对话帮助用户完成[目标]。

# Slots

需要收集的信息：
| 参数 | 必填 | 说明 | 默认值 |
|------|------|------|--------|
| [参数1] | 是 | [说明] | — |
| [参数2] | 是 | [说明] | — |
| [参数3] | 否 | [说明] | [默认值] |

# Rules

1. 每轮只问一个问题
2. 用户提供信息时立即提取并确认
3. 缺失必填项时主动引导，不猜测
4. 所有必填信息收集完成后，汇总确认再执行
5. [其他对话规则]

# Output

信息收集完成后，按以下格式输出结果：
[输出格式定义]
```

## 模板 D：Agent 工作流型

**适用**：自主 Agent、工具调用、自动化工作流

```markdown
# Identity

你是[身份]，负责[核心职责]。

# Tools

可用工具：
| 工具 | 用途 | 调用时机 |
|------|------|---------|
| [工具1] | [用途] | [何时使用] |
| [工具2] | [用途] | [何时使用] |

# Workflow

遵循"思考-行动-观察"循环：
1. **思考**：分析当前状态，决定下一步
2. **行动**：调用合适的工具
3. **观察**：分析返回结果，判断是否足够

# Resilience

- 持续工作直到问题完全解决
- 工具调用失败时：分析错误原因 → 尝试替代方案 → 不得直接放弃
- 遇到歧义时：向用户确认，不做假设

# Pre-action Reflection

调用任何工具前回答三个问题：
1. 为什么调用这个工具？
2. 期望获取什么数据？
3. 这如何帮助解决用户的问题？

# Output

[最终输出格式]
```

## 模板 E：研究分析型

**适用**：调研报告、竞品分析、文献综述等需要引用来源的场景

```markdown
# Task

[研究/分析目标描述]

# Process

1. 将主题分解为关键研究问题
2. 针对每个问题独立检索和分析来源
3. 将发现综合为连贯报告
4. 在结尾标注信息缺口和局限性

# Citation Rule

- 每个具体论断必须引用来源：[来源编号]
- 无可用来源时注明"一般性估计"或"基于通用知识"
- 禁止无来源的断言性陈述

# Output Format

## [研究问题1]
[分析内容，含引用]

## [研究问题2]
[分析内容，含引用]

## 综合结论
[跨问题的综合分析]

## 参考来源
[来源列表]

## 局限性
[信息缺口和分析局限]
```

---

## 使用说明

1. 根据使用方式选择基础模板
2. 将技巧选择阶段确定的技巧模板片段嵌入对应区域
3. 根据目标模型选择标记语言
4. 移除不需要的可选区域（如无需 Examples 则删除）
5. 确保最终提示词是完整可用的，不含任何占位符
